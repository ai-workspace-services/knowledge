## 2. 用户与核心身份：正确目标

目标是保留并验证**源一致性快照定义的真实用户集合和身份语义**。当前基线 33，不使用“33+3=36”，也不把 33 固定为未来永久数量。目标已有事实先分类，再由审核过的增量规则处理，不能为凑数量删账号。

| 维度 | 目标与验收 |
| --- | --- |
| 用户集合 | 快照内用户全部存在，无漏迁或重复；目标独有记录逐项说明，不能自动认定可删除 |
| 稳定身份 | uuid、proxy_uuid、邮箱、用户名、密码哈希及 MFA 状态/材料保留，关联身份唯一键和外键有效 |
| 权限及生命周期 | role、level、groups、permissions、active、归档及生命周期字段按合同核对；禁止启动时默默替换 |
| sessions 与 MFA 关联表 | 按各自快照记录核对，不套用用户数。UAT 域名、会话签名/加密密钥及有效期单独检查；不保证复制生产 Cookie 可直接登录 UAT |
| 种子处理 | 已存在账号不由 bootstrap 重写密码、权限、MFA 或状态；仅对真正全新空环境创建缺失种子，冲突即停止并列出方案 |
| 获准例外 | 历史仅允许明确 sandbox 代理 UUID 差异；review 密码/组、sandbox 版本字段等其他差异不自动豁免 |
| 增量与冲突 | 相同稳定键与内容为空操作；源变化、目标独立变化及同键冲突分别识别，不做无条件整行 UPSERT |

### 实施顺序

1. 固定源快照、目标基线、工具版本及校验和；保存目标备份和恢复点。源保持服务，迁移连接只读。
2. 修复 Accounts 内置账号初始化：保留已有身份，不因每次启动生成新哈希或重复写入。变更经过 PR、检查、不可变构件发布及目标部署后，再重验。
3. 使用预构建 migratectl 的真实帮助和审核范围生成增量预览；工具缺少在线追加能力时先补工具，不改用临时 SQL 整行覆盖。既有 copy-full-business 的空目标路径不能直接应用到当前有数据目标。
4. 绑定确切源/目标、快照、schema、目标基线及计划摘要；目标通过工具支持的锁/事务协调写入。只有确实暂停目标写入时才传 writers-paused，不能把 UAT 无外部流量当作无后台写入。
5. 事务应用后检查全部身份与关联表；前后比较敏感值只在受控内存中进行，公开证据不输出值或认证数据摘要。
6. 同一不可变输入连续执行至少 3 轮，证明无重复用户/关联事实、无意外更新或版本增长；源继续写入时不能拿三个不同快照充当三轮零差异证明。另验证服务重启不重写身份。
7. 由持有者用既有凭据与 MFA 登录，验证角色权限及套餐、配额、余额和策略。源继续在线，目标不是生产权威写入者，生产切流 NOT_RUN。

## 3. Vault：平滑迁移分为 UAT 消费者切换与生产服务切换

本轮目标是完整快照在隔离 UAT 正确恢复，并把 UAT ESO 迁到目标 Vault。生产 Vault 域名、DNS、身份及消费者迁移不包含在本轮，需单独制定最终增量与切换决策。

### A. 建立恢复点及隔离目标

- 保留现有 File 实例和 PVC；Raft 使用独立 PVC，不把 File 数据目录原地改为 Raft。
- 固定源快照 SHA-256、版本、采样时间，确认 snapshot inspect、解封阈值与材料匹配。快照完整性检查不等于已验证可恢复。
- 目标先实施网络隔离，阻断源 Raft 地址、生产外部依赖及公众访问；不加入源 Raft 集群，不在源生成、撤销或修改身份。

### B. 恢复与完整性核对

- 仅在新空 Raft 目标完成受支持的初始化、快照恢复与解封流程。验证后端确为 raft，版本、存储路径及 PVC 对应正确。
- 按同一快照边界核对挂载、KV 版本/metadata、策略、身份和认证配置清单；敏感数据只在受控通道比对，不输出值。核实 cubbyhole、租约和临时 Token 的时效语义，不宣称所有运行态租约可跨环境继续使用。
- 复制快照可能复制生产 Token 和外部认证配置，Cluster ID 不足以证明隔离。验证完成后，在目标撤销复制的可用 Token，限制/关闭生产认证入口，建立独立 UAT 操作身份；全部操作必须校验目标地址和身份，源端不动。

### C. 建立 UAT 专属访问

- 优先建立 Kubernetes 工作负载身份，绑定 ESO 专用 ServiceAccount、命名空间和 audience，Vault 登录后签发短 TTL Token；TokenReview 权限及 API egress 最小化。
- UAT 专属策略仅允许所需键及 metadata 操作。分别用管理身份核对完整性、用 ESO 身份验证授权范围及越界 403。
- 目标 Vault 通过 TLS 提供消费者访问，验证 CA 和服务名；当前恢复目标的隔离 HTTP 监听不能直接开放给 ESO。
- 先创建平行 SecretStore 与 ExternalSecret 影子目标，避免覆盖现有业务 Secret。比较所需字段是否存在、证书有效性和派生配置是否一致，不记录凭据值。

### D. 平滑切换 ESO

1. 新身份登录、允许/拒绝测试、TLS、续期/重新认证和影子同步全部通过。
2. 通过 GitOps PR 将 UAT SecretStore/ExternalSecret 切至新服务；证明同步不是依赖旧缓存，生产 SecretStore 不改。
3. Secret 内容无变化时不重启应用；内容确需更新时仅滚动相关 UAT 服务并确认实际进程读取正确。
4. 验证至少一个实际刷新周期、短期 Token 过期后的重新认证、业务登录及数据库连接。观察窗口记录实际起止，不能把立即 SecretSynced 当作持续可靠。
5. 如仅切换读凭据且新旧无新增写入，回退 UAT GitOps 读取引用；已在目标新增或轮换凭据时先核对消费者及数据差异，禁止盲目回退旧值。

### E. 持久化与收尾

- 对隔离目标写受控探测对象，重建 Pod、重新解封并核对对象和授权行为，保留源快照及目标备份。Shamir 部署重启后需解封，应明确人工流程；自动解封另行设计其密钥管理依赖。
- 解封材料由受控系统托管，避免与 Vault 数据置于同一节点；不通过 CLI 参数、明文临时文件或公开文档传递。交接中“节点上保存 init.json”的做法不是最终托管方案，现有材料不擅自删除。
- Pod 重建、宿主重启和异机灾备分别验收。local-path 仅提供本节点持久性，节点名保持当前值；最终应有异机加密备份及可验证 RPO/RTO。
- 仅在观察窗口与回退验证通过、负责人明确确认后清理旧 UAT 实例；不删除源生产资源。

## 4. 状态、证据与执行提示词

每轮保存 run_id、Asia/Shanghai 实际起止、固定 commit/tag/digest、快照/迁移校验和、源/目标受控身份、阶段、退出码、差异、例外、修复 PR 和重验结果。源码修复、制品发布、部署、迁移、恢复、业务验收与生产切换分别记账。缺证据 BLOCKED，未执行 NOT_RUN。

> 先完成只读预检，按源一致性快照验证真实用户集合，不累加目标初始化账号。保护已有身份和认证材料，先解决应用启动改写账号问题，再用审核过的 migratectl 增量计划与事务执行；同一输入至少 3 轮无业务变化，并验证重启后身份稳定。Vault 先在独立且隔离的 Raft 目标恢复，验证完整性并收敛复制身份，再建立 UAT 专属短期身份与 TLS，经过影子 ESO 同步后由 GitOps 切换 UAT 消费者。任何冲突、越权、错误目标或证据缺失立即停止后续写入。生产服务继续运行，公共 DNS 和生产消费者不变；不把健康接口、文件存储持久化或 Cluster ID 独立作为完整迁移成功证明。
