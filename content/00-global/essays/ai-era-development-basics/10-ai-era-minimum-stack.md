# 10 / 10｜AI 会写代码以后，开发者还需要掌握什么？

## 微信 / 朋友圈

**标题：** AI 会写代码以后，开发者还需要掌握什么？

做完这套图以后，我反而越来越确定一件事：

AI 时代不需要每个人重新背一遍所有语言、框架和 API。

真正值得掌握的是：

**1. Runtime**

代码运行在哪里？

**2. UI / Framework**

页面如何生成和交互？

**3. HTTP / Data**

数据怎么流动？

**4. Service / Storage**

规则和事实分别放在哪里？

**5. Engineering Delivery**

依赖、测试、部署、观测如何闭环？

**6. AI Collaboration**

如何描述约束、拆任务、验证结果、持续迭代？

最后还是回到一句话：

> **先判断边界，再让 AI 加速实现。**

## 小红书

**标题：**

> AI 都可以写代码了，程序员到底还需要学什么？

这是这组 10 张图最后真正想表达的东西。

AI 时代，我越来越不建议把大量时间花在：

背 API、背语法、背框架细节。

真正需要形成的是一个**工程判断框架**。

看到一段代码，先问：

### ① 运行在哪里？

Browser / Node.js / Edge / Server？

### ② 什么时候运行？

首次加载？服务端渲染？用户点击？后台任务？

### ③ 谁拥有数据？

组件？API？Service？Database？

### ④ 失败怎么看？

Logs？Metrics？Trace？Alert？

### ⑤ 怎么证明结果正确？

Test？Schema？Contract？User Experience？

有了这些判断以后，AI 才真正从：

**“自动补全工具”**

变成：

**“工程执行加速器”。**

所以这套图最终只有一句话：

> **想清边界与取舍，比写出代码更重要。**

## X

**Title:** AI lowers implementation cost. It raises the value of judgment.

AI changes *how* we write software.

It does not remove the need to understand software.

The minimum knowledge stack I think matters now:

1. Runtime
2. UI & frameworks
3. HTTP & data flow
4. Services & storage
5. Engineering delivery
6. AI collaboration

Before asking AI to write code, ask:

Where does it run?  
When does it run?  
Who owns the data?  
How does it fail?  
How do we verify it?

**Understand the boundary. Then accelerate implementation.**

## LinkedIn

**Title:** What development fundamentals still matter when AI can write the code?

After putting this 10-part series together, my main conclusion is simple:

The AI era does not require engineers to memorize every API, framework or implementation detail.

It does require a strong mental model of software systems.

Before asking AI to implement something, I believe engineers should be able to answer:

**Where does the code run?**

**When does it execute?**

**Who owns the data?**

**What is the trust boundary?**

**How does failure become observable?**

**How is the result verified?**

From there, the minimum practical knowledge stack becomes:

Runtime → UI/frameworks → HTTP/data → services/storage → engineering delivery → AI collaboration.

AI is exceptionally good at accelerating implementation.

But someone still needs to define the boundaries, constraints and acceptance criteria.

> **Understand the boundary first. Then let AI accelerate the implementation.**

**Engineering Decision Canvas — 10/10**
