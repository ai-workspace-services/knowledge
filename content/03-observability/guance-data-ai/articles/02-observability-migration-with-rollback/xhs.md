# 面板搬家，最难的是查询口径对上

（观测云内容合作；沿用上一篇同一免费专区空间与 UAT 链路）

## P1 原面板
自建 Grafana 跑了很久，数据在 VictoriaMetrics 和 VictoriaLogs。这次不拆它，只挑面板搬到观测云做对照。搬不搬，看验证结果说话：同一口径、同一时间窗，曲线对得上才算数。

## P2 JSON 盘点
先导出仪表板 JSON，盘清 datasource、panel、变量、查询、单位、聚合窗口、阈值、告警。首批只选 3 个：资源健康、API 流量与错误、k6 压测延迟。历史数据不搬，留在原存储。

## P3 AI 映射
AI 读 JSON，给出映射清单和候选配置，每个面板标“可迁移 / 需重写 / 暂保留”。观测云能导入 Grafana JSON，但部分高级特性要手动重配，别指望一键兼容。

## P4 查询陷阱
指标名转换后对不对？rate 窗口和 step 对齐没？histogram 分位数算法一样吗？秒和毫秒混了没？缺数是补零还是断线？变量和时间范围换了没？语法能转，语义要人核。

## P5 生成 HCL / plan
监控意图放 GitOps，renderer 生成 HCL，PR 审完再 plan。有 API 权限的空间才 import / apply；普通免费空间不支持 Open API，只展示离线生成结果，也不走浏览器私有接口。

## P6 双屏对照
Grafana 和观测云同屏，用真实请求加 k6 压测看同一时间窗，峰值、分位数、错误率逐项对。三个面板判定：【待实测】。失败映射：【待实测】。

## P7 回退
新写入有开关，失败不拖垮原采集。配置回退靠 Git 版本加审查后的 plan / apply；数据回退靠原始存储。回退演练耗时：【待实测】。迁走的是排障入口，不是数据主权。

## P8 哪些值得迁移
值得：需要和 Trace、用户体验关联的面板。暂缓：纯基础资源图，自建已够用。修改工时：【待实测】。原 Grafana 入口一直保留，过一个切一个。
