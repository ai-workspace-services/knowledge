# 独立开发观察者计划：AI × 可观测 SaaS 首季策划方案

> **全季核心命题**：AI 如何帮助个人 SaaS 被开发、被理解和持续运行。  
> **核心交付目标**：首合同 12 篇核心主题（微信公众号长文 + 小红书种草图文） + R1–R3 可替换候选池。  
> **工程实践主线**：AI 辅助的 IaC / GitOps / Playbook / Vault 闭环，彻底杜绝 Web 界面手动点击。

---

## 一、合作范围与选题立场

本次首个季度合同按每周一个独立技术主题，规划 **12 篇核心交付**；每个主题以微信公众号深度技术长文为主（InfoQ 客观实战风格，严格 ≤1500 字，3–5 段落，配套架构视角决策表），并同步配套一组小红书种草图文（严格 600–800 字，口语化、P1–Pn 分页排版）。另设 **R1–R3 三篇可替换候选**，用于在缺真实证据、外部权益不满足或双方评估需要微调时无缝替换相近核心篇，不占用额外交付承诺。

读者主角是独立开发者与精简技术团队。自建 Grafana / VictoriaMetrics / OTel 底座与商业 SaaS 可以且应当同时存在。决定 SaaS 采购与留存价值的唯一准则，是它**减少了多少日常运维与排障负担、付出了多少显性与隐性费用，以及在发生技术路线转移时能否低成本退出**。

## 二、整季叙事演化路线

```text
个人 SaaS 已经上线，但一个人需要独自承担开发、SRE、客服与运营
  → 阶段一：接入与平迁（#01–#02）：挑选可观测 SaaS 并接入，AI 辅助将已有自建面板平迁对账并保留回退；
  → 阶段二：端到端穿透（#03–#05）：看见终端真实用户性能瓶颈，串联跨多云分布式 Trace，建立防打扰的可行动告警；
  → 阶段三：Agent 观测与成本（#06–#08）：全链路观测 Coding Agent 工具链执行，对账 Token 与业务交付，捕获死循环重试；
  → 阶段四：发布与排障（#09–#11）：利用观测数据做发布前后比对，AI 辅助夜间异常调查，建立独立外部可用性探测；
  → 阶段五：TCO 复盘（#12）：汇总 90 天完整用量、真实账单与退出演练，科学决定是否继续采购 SaaS。
```

## 三、核心实践铁律：全代码化交付主线

本季所有文章的技术落地，**彻底杜绝在 Web 控制台做任何人肉点按与截屏演示**。全部围绕现代化平台工程与代码化实践展开：

1. **GitOps**：只存放非敏感环境参数、服务元数据与监控意图声明（YAML），严禁硬编码敏感信息。
2. **IaC-modules**：本地 Renderer 将声明式意图编译为显式 HCL，执行 `terraform plan` 离线验证；普通免费空间不支持 OpenAPI 时仅输出离线 HCL，严禁使用私有 API 逆向绕过。
3. **Playbook**：Ansible 自动化编排 DataKit 守护进程、OTel Collector 路由与双写布尔开关，具备幂等与熔断隔离能力。
4. **Vault 运行时注入**：HashiCorp Vault 动态注入写入 Token、只读查询 Key 与管理凭据，绝不进入 Git 仓库或 CI/CD 构建日志。
5. **AI 角色边界**：AI 负责起草配置声明、解析 AST 语法树、生成 PR 说明与对账分析脚本；人类工程师最终审核 PR、核对 Terraform plan 并执行凭据签发。

## 六、事实依据与合规硬约束

1. **北京免费专区 OpenAPI 约束**：免费空间不支持通过 OpenAPI 读写数据，公开的 Terraform Provider 在免费空间仅用于离线生成与验证 HCL 语法，不宣称自动化远程 apply。商业空间额外权限单独披露。
2. **服务协议第 4.7 条商用授权**：免费版协议明确要求“未经书面授权不得用于商业用途”。XWorkTech 属于商业 SaaS 项目，使用免费版前必须确认书面授权范围，未授权前仅在非商业实验或授权空间验证。
3. **数据安全红线**：客户端 RUM 强制开启 DOM 输入框遮罩；分布式 Trace 严禁携带 JWT 密钥、Cookie、数据库明文密码及大模型 Prompt 敏感原文。
4. **成本真实性**：90 天账单必须严格按照实际工作空间资源量与官方计费单价核算，无账单时必须标注“假设估算”，严禁编造财务收益。
