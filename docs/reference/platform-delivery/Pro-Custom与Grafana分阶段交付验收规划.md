# Pro Custom 与 Grafana 分阶段交付验收规划

日期：2026-11-03。状态：实施待排期，所有运行验收 `NOT_RUN`。需求：[Knowledge #351](https://github.com/ai-workspace-services/knowledge/issues/351)。[完整规划](Pro-Custom与Grafana升级完整规划.md) · [产品](Pro-Custom专属资源工作台规划.md) · [持久化](Grafana独立PostgreSQL与GitOps持久化规划.md) · [恢复](Grafana面板丢失排查与恢复规划.md) · [隔离](Grafana租户隔离与Portal嵌入规划.md)

## 1. 执行边界

本轮先落地文档；不代表已恢复面板、迁移数据库、开放客户功能或完成生产切换。后续每阶段独立任务、owner PR、固定制品和验收回执，不把文档合并当作运行交付。

保持既有交付入口与仓库 owner，按实际手动/Ansible + GitOps + Flux 流程实施；不要求先实现新流水线，不改变现有入口网关。先完成最小面板恢复，再引入持久化与租户能力。

## 2. 仓库与职责矩阵

| Owner | 交付内容 | 不承担 |
| --- | --- | --- |
| Knowledge | 本组文档、决策、状态与证据索引 | 运行资源、凭据或部署脚本 |
| Portal | 四路由、权益交互、身份入口和嵌入外壳 | 云厂商执行、Grafana 内部 SQL 写入 |
| Accounts/权益与资源服务 | 套餐能力、成员与节点归属、报价/额度/任务授权契约 | 由 Grafana 决定计费归属 |
| 观测实现 owner | 面板/指标契约、租户配置同步、受限查询能力 | 平行的通用云资源编排 |
| Artifacts | 通用 Chart、配置与插件包装、不可变制品 | 环境参数、生产部署 |
| GitOps | 环境声明、版本 pin、面板包与非敏感秘密引用 | 执行脚本、密码、运行 CMDB |
| IaC | 需要新增的资源与权威运行事实 | Grafana 业务配置和主机执行 |
| Playbooks | 身份、备份、恢复、迁移、服务配置和验证执行 | 第二份环境拓扑或资源权威 |
| 控制面 | 授权、派发 owner、等待和脱敏回执 | 重复实现备份迁移或 provider 操作 |

执行实现跨仓扇出到独立 PR，全部回指本规划和后续实施任务；生产数据写入/流量交接使用实际已批准的变更路径。

| 阶段 | 输入与工作 | 必须产物 | 放行条件 |

## 5. 回执和放行规则

每次验收保存 feature/task ID、源 SHA、应用/Chart digest、面板包版本/checksum、环境标识、实际用户职责、开始/结束时间、预期与实际、退出码、结果及脱敏证据引用。运行环境和敏感详情存受控证据，公开文档不复制部署目标或凭据。

检查状态仅使用 PASS、FAIL、NOT_RUN、BLOCKED；空响应、检查跳过、权限不足、上游不可用不能折算 PASS。CI 成功、Pod Running、Flux Ready 和健康接口绿色只是部分证据；至少有用户 UI、实际数据源查询、租户拒绝和恢复演练证据。

升级前基线应捕获所有组织/成员/数据源/标准及自定义面板清单和权限，不只保存数量；必要的内容摘要按对象类型规范化比较。允许差异来自明确批准的变更清单。

## 6. 切换、观察和回退

每阶段定义当前写者、停止条件、回退资产与责任角色。保留可用源和失败目标；无证据不删除旧卷、旧数据库、备份或旧身份。数据库切换只作用 Grafana 单元，不捆绑 Accounts 数据库或节点采集切换。

建议正式放量后至少观察一个完整日周期，并覆盖采集新鲜度、查询错误、组织同步、权限和备份。该时长为建议，实施变更单须确认实际窗口及阈值。观察内发现 UID 丢失、越权、解密失败或持续查询错误，停止继续放量并按阶段回退。

目标产生新写入后，不能直接切旧库丢弃新增状态；先明确恢复点和增量核对。镜像降级不代替 schema/数据恢复。源清理必须在观察完成、恢复证据齐备后按精确清单另行决定。

## 7. 待定决策与关闭条件

- Accounts 的有效 Pro Custom 能力标识、额度、报价和到期后资源保留规则。
- 独立 PG 的承载、容量、版本兼容、备份/PITR 和恢复目标的实际验证。
- Grafana 拟用版本的迁移身份/运行权限、组织配置 owner、受限查询代理方案。
- 标准面板 UID 清单、历史指标归属、成员撤销生效时限和观测数据保留期。
- 实施责任人、实际排期、生产变更窗口及回退 owner。

本次文档任务可在文档 PR 合并并验证后关闭；后续运行实施需独立任务承接上述验收，不随文档 Issue 关闭而宣称产品或故障闭环完成。
