# Team Proxy 节点登记、分配与审批

## 行为

Team 节点使用已有共享部署凭据认证，并声明 `resourceClass=team` 后，可以先登记到管理端。`teamId` 可为空；填写时仅表示建议团队。共享凭据完成部署身份认证，不会自动授予团队用户访问权限。

管理员在区域入口页下方的 Team 节点分配清单查看节点 ID、在线状态、区域、建议团队、审批状态和实际归属。Root 管理员选择已存在的团队，填写操作原因，执行批准、拒绝或停用。读取权限与分配写权限分离，操作与授权更新在同一数据库事务中审计，并使用版本条件避免覆盖并发决定。

- `pending`：待分配，不下发用户。
- `approved`：只下发管理员分配团队的有效成员。
- `rejected` / `revoked`：下发空用户快照，用于清除已有授权。

管理员分配结果优先于节点建议。重复心跳不会覆盖分配、拒绝或停用决定。团队变更必须先停用，待节点上报正确的空配置版本、零用户、成功同步时间及正常状态后，再分配新团队。客户端入口在节点应用当前批准版本前保持关闭。不得回退到公共节点。原有独立团队凭据的严格绑定继续兼容。

节点类型与 VLESS 传输路径无关；默认路径仍为 `/split`。

## 接口与部署顺序

Accounts 新增 `GET/PUT /api/auth/admin/agents/team-enrollments`；Console 通过已有会话代理调用。新增表 `team_agent_enrollments`，前向迁移版本 `2026102002`，原生空库与全业务快照契约同步更新。恢复授权存储不可读时不允许下发托管节点授权。

发布顺序：审核并应用数据库迁移 → Edge Agent → Accounts → Console。Knowledge 提供构建时的中英文管理文案。此次仅修改和本地验证，不代表生产发布、节点注册或真实连接已验收。

## 本地验证

- Accounts：API、Store、Agent Registry、数据库迁移与原生 SQL 契约测试。
- 隔离 PostgreSQL 17：登记幂等、管理员决定持久化、并发旧版本拒绝，以及审计失败时授权更新回滚。
- API 联调：空 teamId 登记、管理端可见、管理员覆盖建议、团队用户隔离、停用清空、禁止公共范围降级、重新分配等待撤销确认。
- Edge Agent：接受待审核空配置和管理员实际分配，拒绝待审核携带用户、未知状态与缺失团队的批准响应；配置、同步与 Xray 测试。
- Console：审批请求携带版本和原因、冲突不自动重试、停用不提交建议归属、错误显示，以及类型检查、lint 和 Webpack 生产构建。
