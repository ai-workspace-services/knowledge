# 支付 MFA 建议与人工审核账户恢复

支付、购买订阅、同周期升级和账单门户不再要求先绑定 MFA。未绑定或尚未完成 MFA 的用户看到安全风险提示，但购买按钮仍可使用。已绑定用户的登录 MFA 保持有效；退款、取消及管理端敏感操作继续遵循各自验证要求。

## 同页恢复

`/account-recovery` 同时保留自助密码恢复和 MFA 解除申请。密码恢复不会解除 MFA；MFA 解除申请不会修改密码、订阅、身份标识、配额或账本。

MFA 恢复顺序：用户请求邮件验证码 → 验证已绑定邮箱 → 填写原因并明确授权 → 持久化待审核申请 → Root 核验身份 → Root 输入审核理由及当前 MFA 验证码 → 系统执行批准或拒绝。

邮箱验证码仅授权提交申请，不直接解除 MFA。验证码与密码恢复独立，哈希保存、30 分钟过期、最多五次验证失败；发送受 IP、邮箱及账户冷却限制。申请有效期七天。未知、未验证、未启用 MFA 或停用账户的发码响应一致。

## Root 审核

只有 Root 可访问审核队列及执行审核；普通管理员、运营者与用户均不可审核。Root 不能审核自己的申请。操作要求审核理由及 Root 当前 MFA。审批绑定申请 ID、目标用户、邮箱和原 MFA 配置指纹。

批准在同一数据库事务内解除旧 MFA、撤销一次性恢复码、删除全部旧会话、记录审核结论并写入审计。审核重复、申请过期、账户状态变化、邮箱变化或重新绑定 MFA 时停止执行。拒绝不改变用户 MFA。用户应在恢复后重新登录，建议重新绑定 MFA。

进行中的 MFA 登录与审批持有同一用户锁：审批完成后，旧因子不能再创建新会话。审核结果通过账户邮箱通知；通知失败不会回滚已经提交的安全操作，可通过审计记录追踪。

## 回归检查点

- 无 MFA 用户能够到达 Stripe 购买、预览、重试和账单门户逻辑，原有只读账户限制仍有效。
- 用户未明确授权、验证码无效或超限时不可进入审核。
- 邮箱确认后旧 MFA 仍有效；只有 Root 审核可解除。
- 非 Root、错误 Root MFA、本人审核、过期及重复审批均被拒绝。
- 并发审核只执行一次；会话、恢复码和审计随审批原子提交。
- 重新绑定 MFA 后旧申请不可解除新配置。
- `/account-recovery` 密码恢复流程继续可用，两个流程互不复用验证码。
