# 订阅生命周期与审核退款：实现及审查契约

状态：业务规则已确认，代码及验收仍在进行。本文件不是生产功能已上线的证明。

关联实现：[Accounts #251](https://github.com/ai-workspace-services/accounts/pull/251)、[Portal #451](https://github.com/ai-workspace-services/portal/pull/451)。中英文权威文案位于 `content/website/account/billing-policy/`；Portal 构建时读取，不在组件中复制政策。

## 三层职责

| 层次 | 责任 |
| --- | --- |
| 常规自动化 | 资格、用户级滚动 30 天门禁、并发互斥、签名预览及状态版本校验；用户确认后的升级、期末降级和取消；权益与账本核验；退款证据准备；对账与恢复 |
| 人决定、系统执行 | 管理员以资金写权限、MFA、理由及状态版本批准或拒绝退款；批准固定付款集合、币种和逐笔金额上限。系统逐笔幂等退款、记账、恢复及终止订阅，不要求管理员到 Stripe 逐笔操作 |
| 人工审计异常 | 无法证明的首购历史或迁移映射、付款归属、无法拆分的混合账单、非本系统 Schedule、长期对账异常、币种金额异常、无法继续的部分退款、取消后恢复、政策例外、异常锁解除及申诉 |

## 不可绕过的边界

- 首购绑定用户完整历史及迁移身份映射，不绑定当前订阅 ID。窗口为可信首次成功付款后 72 小时，取首次服务器申请时间；升级、迁移、重新申请均不续窗。无法核实标记待核查，不伪装为已拒绝。
- 升降级合计每位用户滚动 30×24 小时一次。取消独立，不需要管理员批准，不被升级冷却期挡住。首次购买、自动续费、到期不占次数。
- **已确认收紧规则**：退款待审核期间禁止升级／降级，保留原付费使用及取消续费。申请固定付款清单，避免新增差价让审批金额失效。
- 审批执行期间冻结冲突套餐操作。批准不是可反复使用的“允许退款”开关；付款集合、币种、逐笔金额、状态版本必须一并绑定并在执行前重新校验。
- 本地永久保存操作、执行子步骤、provider 引用及审计事件。[Stripe 幂等键至少 24 小时后可能被清理](https://docs.stripe.com/api/idempotent_requests)，不能把旧键当成永久去重保障。跨时段重试先查询远端，无法证明未提交则保留锁并人工核查，不能盲目再次 POST。
- 超时不等于失败。已提交但结果未知只能重试或对账原操作，不能放行新单。
- 一笔成功后不能重退；部分成功不得报告整体成功或逆向回滚。资金全部退完但订阅终止失败，只恢复终止步骤，不再次退款。全部金额确认成功且订阅终止后才转 Free。
- PAYG、超额费用不进入订阅退款或差价抵扣，不换汇。移除 5% 用量限制后，不得用高用量变相自动拒退。共享 IP、多账号、频繁申请仅标记或限流，不自动定罪。
- 人工异常处理也需权限、MFA、理由、版本和审计；禁止直接改数据库清冷却或删财务记录。

## 正常路径

无有效付费订阅可购买任一套餐；已有付费订阅修改原订阅，不创建重复订阅。Plus→Pro 月付按剩余同周期补差价，核验付款及 webhook 后额度 20GB→50GB，保留已用量、不叠加、不清零。月付升级年付留待下一批。

Pro 年付可在期末降至 Pro 月付或 Plus；Pro 月付可期末降至 Plus；转 Free 使用期末取消。Schedule 必须能证明属于原订阅和本系统，不能覆盖来源不明的 Schedule。保留当期价格、已付费有效期及配置，无中途抵扣。目标续费失败不得续长旧高档权益；Free 按自然月规则防止反复赠额。

## 合并与运行边界

- 代码、向前兼容迁移、测试、Stripe Sandbox、Knowledge 内容及证据可自动推进；历史迁移和 checksum 不改。
- 人重点审查金额算法、资金权限、并发、恢复、迁移安全与政策一致性。
- PostgreSQL 17 跨实例并发、回滚、重启恢复和关联完整性，以及真实 Stripe Sandbox 排期、取消、退款、webhook 均为门禁。离线 HTTP fixture 不等于 Sandbox 验收。
- Portal 针对性测试、类型检查、Lint、构建必须通过；主线既有失败单独列出，不能豁免本次新增失败。
- 全部门禁通过并经人工审查批准后才合并；CI 全绿不是人工审批。
- 本轮不部署 V3、不切 DNS、不修改 V2、不执行真实生产退款。
