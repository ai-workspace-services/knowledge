#### 第 2 篇　外部层：CDN、边缘与安全

*→ 参见：第 8 章（边缘安全/零信任）*

- **2.1 CDN 与边缘**：CDN 从“静态文件加速”发展为可编程的边缘平台。
- **2.2 边缘安全**：防护从机房出口的硬件防火墙，前移到边缘的 WAF、Bot 管理与抗 DDoS。

#### 第 3 篇　网络层：从机房布线到软件定义

*→ 参见：第 2 章、第 5 章（SDN/VPC）*

- **3.1 互联与容灾**：多机房互联支撑了容灾形态的升级：异地灾备、异地多活，再到按单元（SET/Cell）部署。
- **3.2 核心 / 汇聚 / 接入**：经典的三层园区网模型在数据中心里逐步让位给 Spine-Leaf 和 EVPN-VXLAN。
- **3.3 SDN 与虚拟网络**：Open vSwitch 与 Overlay 让网络随虚拟机、容器一起被软件定义。

#### 第 4 篇　接入层：负载均衡与网关

*→ 参见：—（现有章节未覆盖）*

- **4.1 四层负载均衡**：LVS + Keepalived 是开源四层负载均衡的经典组合，商业 ADC 是另一条路线。
- **4.2 七层负载均衡与 API 网关**：Nginx 把七层分发带进千家万户，Envoy 与 Kubernetes Gateway API 把它变成声明式、可编排的网关。
- **4.3 反向代理缓存**：Squid、ATS、Varnish 曾是自建缓存层的主力，大部分缓存职责已上移到 CDN 边缘。

#### 第 5 篇　应用服务层：运行时与发布

*→ 参见：第 6 章（发布）*

- **5.1 Web 服务与运行环境**：从 LAMP 和 Java EE 应用服务器，到容器化的云原生运行时。
- **5.2 配置管理与发布**：经典表列出 SaltStack + Jenkins + GitLab + SonarQube 的工具链。

#### 第 6 篇　业务与服务治理层

*→ 参见：—（现有章节未覆盖）*

- **6.1 业务实现**：业务被拆成用户、商品、订单、支付等服务，靠 API 网关串起来。
- **6.2 服务治理**：SOA 框架（Dubbo）与 Spring Cloud 把治理能力写进 SDK，Service Mesh 再把它下沉到基础设施。

#### 第 7 篇　分布式层：消息与流

*→ 参见：第 7 章、专题一（消息/流）*

- **7.1 消息队列**：经典表并列 ActiveMQ、RabbitMQ、RocketMQ、Kafka、ZeroMQ。
- **7.2 流处理与 CDC**：消息不仅是解耦工具，也成了实时数据的主干。

#### 第 8 篇　存储层

*→ 参见：第 2 章（存储虚拟化）、第 3 章（S3）*

- **8.1 单机存储与扩展**：从机械盘 + RAID 到 NVMe SSD，从 rsync + inotify 同步到快照与云原生备份。
- **8.2 共享存储**：NAS、SAN、iSCSI 仍在企业里服役，但在云原生场景中逐步被对象存储与 CSI 卷替代。
- **8.3 分布式存储**：经典表把 GlusterFS、MooseFS、Ceph、FastDFS 放在一起。

#### 第 9 篇　数据层

*→ 参见：第 7 章、专题一*

- **9.1 数据访问层与分片**：经典表时代靠中间件（TDDL、Cobar、Atlas、MyCat）做分库分表。
- **9.2 缓存**：Memcached 到 Redis，再到 Redis Cluster 取代 Twemproxy、Codis 等代理分片方案，Valkey 成为开源新选项。
- **9.3 关系型、NoSQL 与时序**：MySQL 高可用从 MHA 走向 MGR，PostgreSQL 持续上升，TiDB、CockroachDB 和云原生数据库普及。
- **9.4 大数据与 AI 数据**：Hadoop 生态（Hive、Pig、Mahout，由 Ambari/CM 管理）是经典表的大数据主角。

#### 第 10 篇　容器与编排层

*→ 参见：第 4 章、第 6 章*

- **10.1 容器编排**：经典表正处在“编排战争”中：Mesos、Swarm、Kubernetes、fleet 并列。
- **10.2 容器运行时与系统**：rkt、LXD、Atomic、RancherOS 等路线退场，containerd/CRI-O 成为标准运行时，容器优化 OS（Flatcar、Bottlerocket、Talos…
- **10.3 网络、存储与弹性**：CNI 从 Flannel、Weave 走向以 eBPF 为核心的 Cilium 与 Calico，镜像仓库以 Harbor 为代表。

#### 第 11 篇　操作系统层

*→ 参见：第 3 章（Linux/cgroup）*

- **11.1 CPU 与内存**：调优对象从物理机变成 cgroup 里的容器，NUMA、HugePages 在 AI 与数据库场景重新变得重要。
- **11.2 磁盘与网络 I/O**：IOPS、IO 调度、TCP 队列等基本功依旧重要，io_uring、BBR 和 eBPF 网络追踪是新的利器。
- **11.3 内核与脚本**：Shell、AWK、Python 仍是运维的手边工具。

#### 第 12 篇　基础设施层与数据中心

*→ 参见：第 2–5 章*

- **12.1 IaaS 与多云**：OpenStack 私有云曾是经典表时代的热门，后来公有云、混合云、多云成为常态，资源通过 Terraform/OpenTofu 声明。
- **12.2 硬件管理**：Cobbler 装机、iDRAC/ILO 远程控制演进为基于 Redfish 的标准化带外管理与裸金属自动化。
- **12.3 IDC 与数据中心**：选址、制冷、供电、网络（“风火水电”）是永恒主题。

#### 第 13 篇　运维产品化与平台工程

*→ 参见：第 6 章、第 8 章、第 10 章*

- **13.1 从 DevOps 工具链到内部开发者平台**：经典表提出“运维产品化”：把项目管理、代码托管、持续交付做成产品。
- **13.2 自动化运维产品**：CMDB、ITSM、作业平台、堡垒机是经典的运维产品“四件套”，如今叠加了 SLO、On-call、混沌工程与零信任访问。
- **13.3 FinOps 与 AIOps**：成本成为可观测的一维，AIOps 从异常检测走向由 LLM Agent 辅助排障、执行 Runbook，关键变更保留人工审批。

#### 第 14 篇　运维服务化与管理体系

*→ 参见：—（现有章节未覆盖）*

- **14.1 运维服务化（OaaS）**：咨询、托管、培训、应急，运维能力以服务形式对外输出，SRE 专家服务成为新的形态。
- **14.2 测试与开发协作**：性能测试、环境规划、CI 是运维与研发的接口。
- **14.3 管理体系**：ITIL V3、Six Sigma、PMBok 构成了经典的管理知识体系。

#### 终篇　两条趋势线

*→ 参见：第 1 章、第 6 章、第 10 章*

- **15.1 运维发展趋势**：岗位形态从“什么都干”走向分层、场景化、自动化，再到平台工程与 SRE，下一站是 AIOps / Agent 运维。
- **15.2 自动化演进趋势**：标准化、工具化、Web 化、服务化、智能化、产品化是经典表给出的路径。
